# DNS Automation

AgentDomain keeps Spaceship Basic DNS authoritative and separates two ownership
classes:

- **System-managed records** support managed routing, Cloudflare SSL,
  verification, and professional email. They are visible but read-only.
- **User-managed records** are controlled from the dashboard, REST API,
  TypeScript SDK, MCP, AgentKit, or ElizaOS and count toward the plan allowance.

All Spaceship-writable types are available: `A`, `AAAA`, `ALIAS`, `CAA`,
`CNAME`, `HTTPS`, `MX`, `NS`, `PTR`, `SRV`, `SVCB`, `TLSA`, and `TXT`.

## Safe reconciliation

AgentDomain reads the current provider snapshot and applies only changed,
removed, or added managed records. Provider-only records are preserved. The
platform does not use Spaceship force replacement.

Bulk changes require a dry-run preview and revision token. If DNS changes after
the preview, apply stops with `DNS_REVISION_CONFLICT`. If a provider operation
partially fails, AgentDomain attempts to restore the previous snapshot and
records the failure without exposing provider credentials or raw internal
responses.

## Import and export

The dashboard and API accept standard BIND zone text up to 256 KiB and 200
records. The dashboard also provides structured JSON multi-record entry using
the same typed contract as the API and SDK. Import and batch operations support
merge and replace modes. Replace never removes system-managed records and
requires explicit confirmation in the dashboard.

Use `GET /api/v1/agents/:id/dns/capabilities` as the machine-readable contract
for autonomous clients.

## Plan allowances

Included supports 20 user records, Starter 50, Pro 100, and Enterprise 200.
System-managed records do not consume this allowance. All plans receive the
same validation, locking, rollback, and provider-preservation behavior.
