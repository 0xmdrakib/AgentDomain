# DNS Automation

AgentDomain uses Spaceship Basic DNS as the authoritative DNS provider and writes the
baseline records required for web routing, email, and SSL challenges.

## Baseline records

- Apex `ALIAS` pointing to `CLOUDFLARE_SAAS_FALLBACK_HOSTNAME`
- Cloudflare for SaaS validation TXT records when required
- MX, SPF, DKIM, and DMARC records when email is enabled

## Custom DNS records

Agents can add DNS records through:

```http
POST /api/v1/agents/:id/dns
```

Supported record types are `A`, `AAAA`, `ALIAS`, `CNAME`, `MX`, `TXT`, `NS`, and `SRV`.
System-managed apex, Cloudflare validation, and SES mail records cannot be
edited or deleted by users.

## External apex hosting

Adding a user-managed apex `A`, `AAAA`, `ALIAS`, or `CNAME` transfers web
routing ownership to the external hosting provider. AgentDomain then:

- removes its managed apex route;
- deletes the Cloudflare for SaaS custom hostname and DCV records;
- preserves MX, SPF, DKIM, DMARC, and all other user records; and
- blocks AgentDomain SSL reconfiguration while external apex routing is active.

Deleting the last external apex route reverses the transition and provisions
AgentDomain-managed routing and Cloudflare SSL again. Both transitions are
idempotent and reconciled if a provider is temporarily unavailable.
