# AgentDomain Documentation

The official AgentDomain documentation is available at
[docs.agentdomain.app](https://docs.agentdomain.app).

It covers the product, [public API](https://api.agentdomain.app/api/v1), SDKs,
integrations, smart contracts, authentication, idempotency, limits, and
user-visible lifecycle behavior.

Documentation contributions should keep examples accurate, reproducible, and
free of credentials or customer data. Public contract changes must update their
related documentation and tests in the same pull request.

## Machine-readable Outputs

The static Astro build generates these resources from the public docs,
reviewed HTTP contract map, shared Zod schemas and package manifests:

- `/llms-full.txt`: every allowlisted public documentation page in one text file.
- `/openapi.json`: OpenAPI 3.0.3 for explicitly documented HTTP routes only.
- `/api-index.json`: docs, HTTP operations, SDK exports and MCP tool discovery.
- `/.well-known/agentdomain.json`: project-defined documentation discovery.

`public/llms.txt` remains the short entry-point index. The four generated files
are written only to `dist/`; do not maintain independent generated copies in
`public/`. `scripts/public-api-contract.mjs` owns the reviewed HTTP mapping.
The generator refuses routes absent from the HTTP reference or documented routes
without a reviewed mapping. SDK/MCP onchain functions are not invented REST paths.

The build records deterministic source hashes and workspace package versions,
not build-time timestamps or an assertion that npm publication has happened.
Response projections deliberately mark unspecified fields. Shared Zod runtime
refinements, ownership and payment authorization remain authoritative; OpenAPI
cannot replace them. Legacy provider-specific nested snapshot details are not
expanded in this documentation catalog.

The site uses Astro's Zod 4 while public shared contracts use Zod 3. Keep both
dependency boundaries intact; the build-time converter accepts the Zod 3 inputs.
Generated files retain the static Workers asset boundary and exact MIME headers.
Do not add authenticated server handlers or credential-bearing generation inputs.

## Validation

Build the public shared package before checking docs from a fresh checkout:

```sh
pnpm --filter @agentdomain/shared build
pnpm --filter @agentdomain/docs check
```

The tests validate schema derivation, deterministic generation, canonical links,
source version metadata, error/payment/privacy boundaries and HTTP-style parses.
Output validation checks the actual built files with Swagger Parser, forbids
external schema resolution, and compares generated bytes with current source.
If source changes during a build, rebuild before validating its output.

For local Workers asset verification only, run `wrangler dev --local --env preview`
after a build and check the four resource paths and integration pages. This does
not publish a site. Python framework examples have their own native dependency
locks and qualification harnesses; a docs build is not an LLM or wallet test.
