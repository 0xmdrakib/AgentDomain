---
title: Registration guide
description: Plan, quote, pay for, and track an AgentDomain identity without duplicate checkout.
---

## 1. Choose the owner and bundle

Decide which wallet will own the AgentID NFT and optional onchain names. The paying wallet can be
different, but only the final owner can perform owner-only actions later.

Choose:

- a domain label and supported top-level domain;
- a registration term from 1 through 10 years;
- whether to add Basename or ENS;
- a primary email username;
- an Included, Starter, Pro, or Enterprise plan.

## 2. Check availability and quote

Use the SDK or public endpoints:

```ts
const availability = await agentDomain.checkAvailability('research-agent', { tld: 'com' });
if (!availability.available) throw new Error(availability.reason ?? 'Name unavailable');

const quote = await agentDomain.quote({
  preferredName: 'research-agent',
  tld: 'com',
  registerBasename: true,
  registerEns: false,
  emailUsername: 'agent',
  premiumPlan: 'included',
  years: 1,
});
```

Display `totalUsdc` and the itemized components before requesting payment. Availability and prices
can change, so do not cache a quote as a guaranteed reservation.

## 3. Register once

Send `Prefer: respond-async` and handle the x402 challenge by submitting the exact signed request
once. Keep the `registrationId` and `statusUrl` returned by HTTP `202`. Acceptance is not completion.

SDK 0.9.0 adds `submitRegistration()` for this acceptance response and updates `register()` to
wait using authenticated status GETs. SDK 0.8.x and earlier can mistake `202` for a final result.
See [asynchronous registration](/sdk/typescript/#asynchronous-registration) and the
[upgrade notes](/sdk/typescript/#upgrading-from-08x).

If the response is `processing`, poll or display the accepted state rather than starting another
paid registration. A second checkout can represent a distinct payment intent.

Status reads require the payer's SIWE cookie or `X-Agent-Signature`, not an agent API key or a
payment proof. The payer may differ from the designated NFT owner. Reuse a fresh read signature
between polls instead of prompting on every request. A timeout or abort stops local waiting, not
the accepted purchase. Never automatically resubmit after a lost response.

## 4. Confirm readiness

Before advertising the identity, wait for registration status `completed`, meaning the identity
and all selected services are ready. Payment settlement and an agent ID are not enough. DNS,
HTTPS, email, and selected names can require additional time after acceptance. Estimates may be
unavailable and completion is not guaranteed to be instant.

`action_required`, `failed`, `refunded`, and `awaiting_payment` stop the SDK waiter with a structured
diagnostic. Inspect the state rather than assuming a new payment is needed. A completed status may
lack `result` for older records; the SDK preserves the handle and reports
`completion_result_unavailable` instead of inventing transaction or NFT fields.

## 5. Prepare continuity

After the AgentID NFT is available:

1. Read the [renewal status](/guides/renewal/).
2. Fund the identity's vault for the expected renewal amount.
3. Have the owner wallet authorize auto-renew if desired.
4. Monitor the public expiry and renewal state.

For raw request fields and response shapes, see the [Registration API](/api-reference/register/).
