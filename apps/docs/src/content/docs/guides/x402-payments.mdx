title: x402 payments
description: Understand AgentDomain x402 v2 checkout with USDC on Base and safe retry behavior.
---

AgentDomain uses x402 v2 for paid API operations. Registration is paid in USDC on Base mainnet,
identified as `eip155:8453`.

## Standard exchange

1. The client sends the intended request.
2. The API returns `402 Payment Required` and a `PAYMENT-REQUIRED` challenge.
3. The wallet reviews and signs an accepted payment authorization.
4. The client retries the same request with `PAYMENT-SIGNATURE`.
5. The API returns the operation result and `PAYMENT-RESPONSE` settlement details.

Use the official SDK for challenge parsing and signing:

```ts
const quote = await agentDomain.quote({
  preferredName: 'research-agent',
  tld: 'xyz',
  registerBasename: false,
  registerEns: false,
});

console.log(quote.totalUsdc);

const identity = await agentDomain.register({
  preferredName: 'research-agent',
  tld: 'xyz',
  registerBasename: false,
  registerEns: false,
});
```

## Safety rules

- Show the amount, asset, network, recipient, and expiry to the wallet owner before signing.
- Retry the exact body associated with the challenge; do not change registration options between
  challenge and payment.
- Never submit an x402 authorization to a different origin.
- Treat a network interruption after signing as an unknown outcome until the original operation is
  checked.
- Do not invent a replacement payment flow when the API rejects or cannot verify a challenge.

The SDK supports x402 v2 only and rejects incompatible challenges. See the
[Registration API](/api-reference/register/) for the public request contract.
